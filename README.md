# canon-mp540-macos

Printing from a current Apple Silicon Mac to a Canon PIXMA MP540, a printer from 2008, with a print driver built locally from [Gutenprint](https://gimp-print.sourceforge.io/) 5.3.5.

## Background

I still have a Canon PIXMA MP540, a printer announced in August 2008, and it still prints fine. Canon dropped its macOS drivers long ago, so for years the only way I could use it was from my 2012 MacBook Pro, stuck on macOS Catalina 10.15.7 and running the Gutenprint drivers instead.

My newer Macs were out of luck. Gutenprint stopped publishing macOS installers, then formally dropped macOS support in 2024, so there was nothing to install on Apple Silicon. When I plugged the printer into my MacBook Pro M4 Pro, macOS detected it over USB ("Canon MP540 series") but offered no compatible software, only generic drivers (HP, Epson dot-matrix, Zebra…) that print nothing usable.

I did not want to keep an old laptop around just to print, so I worked on it with Claude (Claude Code). This repository is the result: `build.sh` compiles Gutenprint from its official source on the Mac that uses it, and `install.sh` installs it as a CUPS driver (CUPS is the macOS printing system) and creates the print queue.

I tested it on November 7, 2026 on my MacBook Pro M4 Pro running macOS 27.2: the first page came out right from Safari.

## Requirements

- Xcode Command Line Tools (`xcode-select --install`).
- An administrator account for installation (`sudo`).

## Usage

```sh
./build.sh            # downloads, verifies and compiles Gutenprint into payload/ (a few minutes, no sudo)
# plug the printer in over USB and turn it on
sudo ./install.sh     # installs the driver and creates the "Canon_MP540" queue
```

The printer then shows up as **Canon PIXMA MP540** in every application's print dialog. Do not add the printer by hand in System Settings: macOS would treat it as a second printer, with no driver.

`install.sh` can run before the printer is plugged in: it installs the driver and stops, reporting that it cannot find the printer. Run it again once the printer is plugged in and on, or after moving it to another USB port.

To remove everything:

```sh
sudo ./uninstall.sh
```

## What the scripts do

### `build.sh`

1. Downloads `gutenprint-5.3.5.tar.xz` from SourceForge into a temporary folder.
2. Verifies its SHA-1 checksum (`65e1ad99e9a3df17d505e719a9123eaa3b50fd67`, as published by SourceForge) and stops if it does not match.
3. Compiles only the CUPS driver: no GUI, no GIMP plugin, no Epson utilities.
4. Generates the printer description file (PPD) for the `bjc-MULTIPASS-MP540` model.
5. Assembles the compiled filter, Gutenprint's XML data and the PPD into `payload/`, then deletes the temporary folder.

It does not need `sudo` and writes only to the temporary folder and to `payload/`, which is not tracked. Two builds from the same source produce a byte-identical `payload/`.

### `install.sh` (with `sudo`)

| What is installed | Where |
|---|---|
| The `rastertogutenprint.5.3` filter and Gutenprint's data | `/Library/Printers/Gutenprint/` |
| The PPD | `/Library/Printers/PPDs/Contents/Resources/Canon-PIXMA-MP540-Gutenprint.ppd` |
| The `Canon_MP540` print queue | CUPS configuration |

Nothing is installed outside `/Library/Printers`: no kernel extension, no background service, and macOS System Integrity Protection (SIP) is left untouched. The files are owned by `root` and writable by nobody else; otherwise CUPS refuses to run the filter. The queue defaults to A4 and is not shared on the network.

### `uninstall.sh` (with `sudo`)

Removes the `Canon_MP540` queue, the `/Library/Printers/Gutenprint` folder and the PPD.

## How it works

A document goes through the usual CUPS chain:

```
PDF  →  cgpdftoraster (macOS)  →  rastertogutenprint (Gutenprint)  →  usb backend (macOS)  →  printer
```

Only `rastertogutenprint` comes from Gutenprint. It turns each page's image into Canon (BJL) commands. CUPS runs it only while printing, with restricted privileges and inside the macOS sandbox. It links only against Apple libraries (`libcups`, `libSystem`, `libiconv`).

The PPD generated by Gutenprint is changed in two places:

- **Filter path:** it points to `/Library/Printers/Gutenprint/filter/` instead of `/usr/libexec/cups/filter/`, which SIP makes read-only.
- **Default paper:** A4 instead of Letter.

## Limitations

- **"Experimental" support:** Gutenprint lists the MP540 in this category. Printing works, but colour and paper settings are less finely tuned than with Canon's original driver. For photos, pick the paper type and a high quality in the print dialog: the default is meant for text on plain paper.
- **Printing only:** the MP540's scanner is not supported.
- **No ink levels or maintenance from the Mac:** head cleaning and nozzle checks are done from the printer's front panel.
- **USB only:** the printer is not shared on the network.
- **PPD format is being phased out:** `lpadmin` warns that CUPS will eventually drop PPD support. It works today, but a future macOS release could break this driver; if printing stops after an update, check this first.
- **Gutenprint updates:** the version and checksum are pinned in `build.sh`. Moving to a newer release means editing them by hand.

## Troubleshooting

**Nothing comes out of the printer.** Check the queue state and the CUPS log:

```sh
lpstat -l -p Canon_MP540
lpstat -o
grep "\[Job" /var/log/cups/error_log | grep -E "^E|stats|Sent" | tail -20
```

- `Sent 0 bytes` and `stats 0B`: the filter received no page. Look for an `E` line just before; it gives the cause.
- `Unknown operator "595,000"`: the PPD contains comma decimals, which `cups-genppd` writes under a locale such as French. `build.sh` forces the `C` locale to avoid this; if the message comes back, make sure the installed PPD comes from a rebuilt `payload/`.

**Jobs are stuck in the queue.** Clear it before trying again, otherwise they all print as soon as the problem is fixed:

```sh
sudo cancel -a Canon_MP540
```
